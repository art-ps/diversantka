# Отложено после плана 6.1 (процедурный генератор уровней)

## Что сделано

Модули `src/gen/`: `rng.ts` (mulberry32, seedOf), `difficulty.ts` (числа по уровню), `templates.ts` (парсер и проверки шаблонов, зеркало), `graph.ts` (граф комнат, двери, ключи), `level.ts` (сборка уровня, таймер, проверка мира).

Факты:
- 26 файлов шаблонов: 2 стартовых (yard, dock) и 24 обычных, включая bend-r, stair-r, fork-r.
- Зеркалятся только шаблоны без up/down (шахта в колонках 29–31 у зеркала уехала бы в 8–10) → 34 шаблона при загрузке.
- У каждого не-стартового шаблона ≥2 слотов врагов (плотность уровня 20 = 2.0), проверяет tests/gen-library.test.ts.
- Тест сборки графа: порог ≥10/100 seed (замер: минимум 8/50 при n 11, 15; первая удача ≤ попытки 11).
- Полный поиск пути в тестах: уровни 3–12, 15, 20, 25, 30. Финальное ревью прогнало 3–100 вручную: 0 падений. Уровни 3…2000 собираются.
- Отпечаток уровней 3…12 (tests/gen-fingerprint.test.ts) вместе с GEN.version: изменился генератор, шаблоны или числа GEN → поднять GEN.version и обновить отпечаток (реплеи v3).

## Решения (Ruling)

- Работа в ветке plan-6-1, не в master; слияние fast-forward — по явному согласию.
- tests/i18n.test.ts: DEV_FILES += gen/templates.ts и gen/level.ts (кириллица в сообщениях разработчика, как room.ts/spawns.ts).
- Зеркало ломало шаблоны с up/down → зеркалятся только mirrorable; добавлены bend-r, stair-r, fork-r. Цена: меньше разнообразия у вертикальных комнат.
- cross: проём в уступе у лестницы 34 — 3 клетки вместо 1 (решатель требует L-1..L+1); тест — авторитет.
- Порог графа ≥20/100 → ≥10/100 seed; гарантию даёт критерий «3..100 собираются». Цена: bomb + 3 двери изредка не соберётся с первой попытки.
- Тайлы двери стоят в комнате со стороны старта (other), у её края к цели: дверь в колонке 38 со стороны цели недостижима. Комментарий DoorEdge поправлен.
- densityOf(20) = 2.0 (план ошибся: 1.7) → ≥2 enemy-слота в каждом не-стартовом шаблоне. Цена: тесные тупики с двумя врагами.
- Финальная волна: бомба сначала в тупике (по спеке), зеркало без meta.slots, комментарий DoorEdge. GEN.version оставлен 1: реплеев до релиза нет.

## Минор (отложено)

- seedOf смешивает целые, не байты: коллизии проверены на 3..39.
- `pick([])` возвращает undefined без защиты.
- Пустое тело слота (`item@`) → голый TypeError без имени файла.
- Позиция flamer-слота не проверяется.
- Проверка дубликатов id только среди оригиналов (файл `x~m` мог бы столкнуться).
- library: flamers на высоте 18.5 висят под гранями блоков (намеренно, уровень головы); closet — единственный с 2 item-слотами (ok: роли не кладут 2 предмета в комнату); у well недостижимые декоративные платформы, патруль в 1 клетке от дыры вниз.
- closet: враг под полкой `=` (косметика).
- Патрули fork, fork-r, well, stair, stair-r, vault пересекают подножие лестницы col 30; патрули на уступе и у подножия лестницы — проверить игрой при плотности 2.0.
- Терминалы могут не поставиться, если ближе к старту нет слота terminal: ceil(n/3) не гарантирован.
- level.ts: кандидаты под терминал не исключают комнату 0 явно.

Исправлено в финальной волне: комментарий DoorEdge, бомба в тупике, зеркало без meta.slots, golden-значение mulberry32 (в gen-rng.test.ts и через отпечаток).

## Для 6.2 (склейка с миссиями)

- `MissionNo` → `number`.
- `missionDef(n)` = ручная миссия или `generateLevel(n).def`; `worldOf(n)` кэширует `.rooms`.
- Цикл импортов missions → gen → world → missions: `BUNKER_START = MISSIONS[2].start` на верхнем уровне src/world/index.ts бросает TDZ, если первым вычислится missions. Выход: вынести `missionDef`/`worldOf` в новый модуль (например src/levels.ts), чтобы missions.ts остался листом, или сделать BUNKER_START ленивым.
- `createArrival`, `startMission`, `next` в src/game.ts зашивают `MISSIONS[2].start`; сгенерированные уровни берут `def.start` (yard: x=9, dock: x=10; мотоцикл 5,22).
- `def.tapes` вместо `MISSION.tapes` в HUD, итогах, `enterTapes`, `tapeFloat`.
- На уровнях с лентами забор включается после сцены прибытия.
- Любое изменение уровней → поднять GEN.version (ловит отпечаток-тест; реплеи v3).
